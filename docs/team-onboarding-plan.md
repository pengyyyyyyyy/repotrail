# 团队入职培训平台规划

## 状态与产品目标

本文记录团队培训平台的产品决策、实现结构和阶段验收条件。团队版已实现内置账号、项目授权、持久化快照与任务、企业知识库、动态阅读起点、课程审核发布、私人持续追问、历史恢复和学习总结验收。现有单人阅读工作区、CLI 与导出能力继续提供。

本地 SQLite 环境已执行功能回归和真实模型课程生成。共享部署采用 PostgreSQL、pgvector、独立 worker 和 Docker Compose，其容器运行与恢复流程需在对应部署环境中实测。各阶段的验收条件用于持续检查交付质量。

RepoTrail 将作为开源、企业自托管的研发入职培训平台发布。培训目标是帮助新研发解释项目的业务背景、系统架构、核心流程和团队开发规范。

首版性能验收目标为约 20 名成员、5 路并发问答、同时执行 1 个后台索引或课程生成任务。实际部署资源、模型服务和知识规模随性能报告一并记录。

## 已确认的产品决策

| 范围 | 决策 |
| --- | --- |
| 发布与部署 | GitHub 开源，企业自行部署并接入自己的资料和模型服务 |
| 登录 | 内置账号，由管理员创建成员账号 |
| 项目权限 | 管理员分配项目成员，成员访问获授权项目的代码、文档和课程 |
| 源码来源 | 支持服务器本地目录，以及使用 HTTPS 访问令牌获取 GitHub、GitLab 等仓库 |
| 知识来源 | 上传 Markdown、文本型 PDF，以及读取仓库文档，由管理员手动更新 |
| 模型管理 | 管理员统一配置模型服务，按项目和成员记录用量 |
| 培训内容 | 管理员生成、修改、审核并发布共享课程 |
| 阅读起点 | 结合项目内容推荐与排序，支持更多候选和用户指定的阅读目标 |
| 持续追问 | 围绕当前项目、课程和源码版本检索后回答，支持恢复历史会话 |
| 会话访问 | 默认仅本人可见，成员可主动向同项目成员分享问答 |
| 学习管理 | 保存阅读进度，成员提交学习总结，管理员按课程目标验收 |
| 示例资料 | RepoTrail 自身源码与明确标注的模拟企业文档，随项目提供 |
| 交付方式 | 分阶段完成全部范围，每阶段交付可运行版本并验收 |

沿用现有 Python 源码分析范围、中英双语 README 和默认中文导览。首版继续支持网页与 Python 命令行使用方式。

## 技术方案建议

以下技术方案已进入实现，兼容性与性能验证随版本记录。

- 保留 FastAPI 和现有源码索引、模型客户端、导出逻辑。
- 使用 PostgreSQL 保存账号、项目成员关系、源码快照、知识版本、任务、课程、会话、学习记录和用量。
- 使用数据库迁移管理版本变化，并提供备份恢复说明。
- 使用 pgvector 保存文档向量，结合关键词检索获取源码符号、配置名、错误码及自然语言相关内容。
- 优先验证适合中文文档和英文代码的本地嵌入模型，并允许配置兼容的嵌入服务。嵌入服务与生成模型分别配置。
- 通过独立 worker 处理索引和课程生成，任务状态保存在数据库中，使用租约与幂等操作处理重启和重试。
- 使用 Docker Compose 提供 Web、worker 和数据库的可复现部署方式。
- 用户身份、项目授权和会话所有权由服务端统一检查，覆盖查询、源文查看、导出、分享和历史恢复入口。

## 核心数据与版本关系

主要实体包括用户、登录会话、项目、项目成员、仓库快照、文档版本、知识片段、后台任务、课程版本、章节、学习会话、消息、分享记录、学习进度、总结提交、验收记录和模型用量。

源码快照保存 Git commit、内容摘要和实际读取的源码。知识片段保留所属项目、文档版本、标题路径、页码或行号等定位信息。模型生成结果和引用绑定当次使用的资料版本。

发布课程保存所用源码与文档版本。管理员更新资料后生成新的草稿，审核后发布新的课程版本。已有学习记录保留对应课程版本，界面提供资料更新提示和课程选择入口。

会话记录消息、选中的课程、阅读位置、引用和生成状态。恢复会话时重新验证当前项目权限。个人问答经主动分享后形成独立分享记录，分享撤回和项目成员移除都应及时生效。

管理员通过应用查看学习进度、用量、已提交总结和验收结果。个人会话内容的应用访问规则按会话所有权和分享记录执行。

## 培训与问答流程

1. 管理员创建项目、添加成员并接入代码与文档。
2. 系统建立带来源和版本的索引，提取真实入口、核心模块及文档结构。
3. 模型根据项目证据推荐阅读起点，说明适合了解的内容。
4. 管理员选择培训目标，生成课程大纲和逐章内容。
5. 管理员修改、审核并发布课程。
6. 成员阅读课程、跳转源码、持续追问，系统保存会话和学习位置。
7. 成员提交学习总结，管理员依据课程目标给出审核意见或确认完成。

课程涵盖业务背景、架构与模块职责、核心执行流程、开发规范和相关运行方式。章节应包含学习目标、解释、相关代码或文档位置以及总结提示。

代码通过符号与语法结构分段，文档通过标题与段落分段。每次追问先限定项目和资料版本，再检索相关内容。长会话采用有限窗口与可追溯摘要管理上下文。

阅读起点由程序提取候选证据，模型结合项目内容进行补充、分组和排序。返回的源码位置由程序检查。候选支持分页或展开，路线按选择生成，调用范围和检索预算可配置。

知识库片段和仓库文档作为检索资料处理。工具操作范围由服务端定义，来源内容中的操作指令作为资料文本处理。

## 第一阶段 · 团队基础与持久化

### 交付内容

- 数据库迁移、管理员初始化、账号创建与停用、登录与退出。
- 项目创建、成员分配及统一项目授权。
- 管理员模型配置和项目、成员用量归属。
- 本地目录与私有 HTTPS 仓库接入，凭据独立加密存储与日志脱敏。
- 持久化源码快照、生成任务与已有导览结果。
- 服务重启后的任务状态恢复、失败反馈和可重试操作。

### 验收条件

- 重启后账号、项目、快照和导览结果可恢复。
- 使用多个账号验证跨项目查询、源码读取、任务轮询与导出权限。
- 私有仓库访问令牌和模型密钥通过受控凭据接口保存，公开响应及日志通过脱敏测试。
- 中断任务可识别并重试，重复提交和重试的数据结果保持一致。
- 现有 CLI、导览生成和导出流程通过兼容性检查。

## 第二阶段 · 企业知识库与动态起点

### 交付内容

- Markdown、文本型 PDF、仓库文档导入与手动更新。
- 文档分段、嵌入、关键词与向量混合检索。
- 来源预览、引用定位、资料版本及删除同步。
- 项目相关的阅读起点推荐、展开浏览及自定义阅读目标。

### 验收条件

- 固定问题集能够检索到预期资料，并可核对引用位置。
- 跨项目检索隔离、资料删除和成员权限撤回均有回归验证。
- 使用代码与文档中的精确名称、中文概念及跨文件问题验证检索效果。
- 通过包含多个入口的示例验证推荐数量随项目变化，并核对入口位置。

## 第三阶段 · 课程发布与持续追问

### 交付内容

- 课程大纲生成、逐章生成、编辑、审核发布和课程版本管理。
- 业务背景、架构、核心流程和开发规范的分层讲解。
- 学习会话、消息历史、阅读位置恢复和个人会话列表。
- 基于项目与课程版本的持续追问、来源跳转、流式响应、停止与重试。
- 个人问答向同项目成员主动分享及撤回。

### 验收条件

- 管理员可以修改草稿并发布，成员能区分所学课程版本。
- 浏览器刷新与服务重启后，可以恢复学习位置和历史消息。
- 多轮追问正确继承当前项目与阅读目标，并根据新问题补充检索。
- 会话内容访问、分享范围、撤回和成员移除通过权限测试。
- 流式中断、重复提交和重试保留一致的消息状态与用量记录。

## 第四阶段 · 学习验收与开源交付

### 交付内容

- 阅读进度、学习总结提交、管理员审核意见及完成确认。
- RepoTrail 自身源码与明确标注的模拟企业资料。
- Docker Compose 部署、初始化、配置、备份恢复与升级说明。
- 可复现的检索、问答、课程质量与性能评测，以及项目和成员用量展示。

### 验收条件

- 完整执行接入资料、生成课程、审核发布、学习追问、提交总结和管理员验收流程。
- 固定问题覆盖业务背景、系统架构、核心流程和开发规范，记录回答正确性、引用支持程度和关键内容覆盖。
- 记录 5 路并发问答与 1 个后台任务下的成功率、延迟、资源占用和模型用量。
- 分别记录模拟服务与真实模型服务的测试结果，以及模型服务、硬件和知识规模。
- 按公开部署说明从空环境初始化，并执行备份恢复验证。

## 后续实施需要验证的技术事项

- 本地嵌入模型的中文检索质量、安装体积、CPU 内存占用和首次索引耗时。
- 兼容模型服务的工具调用、流式响应、取消行为和用量返回差异。
- 文本型 PDF 的标题、页码与段落定位质量。
- PostgreSQL、pgvector 和 worker 的部署兼容性与故障恢复。
- 现有 AST 索引上限与培训目标项目规模的适配情况。

上述项目随各阶段实测更新。公开示例的效果与性能结果会注明测试资料和环境。

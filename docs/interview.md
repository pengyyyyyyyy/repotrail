# 模块学习与面试复核

## 推荐阅读顺序

1. 从 CLI 的 demo 入口运行自带示例，对照 cli.py、service.py 与 formatting.py
2. 阅读 models.py 和 index.py，跟踪符号 ID、起止行和导入别名的生成
3. 阅读 test_index.py，复核参数遮蔽、重载实现和默认参数的处理
4. 阅读 engine.py，画出模型消息、源码工具、结构校验与修订的数据流
5. 阅读 llm.py，理解工具调用接口、超时、错误和用量统计
6. 阅读 server.py 与前端事件，跟踪一次生成从排队到展示的过程
7. 阅读评测集与运行器，区分源码片段核验、符号覆盖与解释正确性

## 能够独立解释的问题

- 为什么将首版分析范围收敛到 Python
- 为什么让模型引用符号 ID，并由程序回填文件与行号
- 函数参数遮蔽、动态派发、继承和 monkey patching 会怎样影响静态关系
- 如何处理父函数中先后调用两个子函数的阅读顺序
- 工具读取与一次修订各自可能带来什么收益和成本
- 模型返回格式错误、接口异常或未知符号时，系统保留了哪些结果
- Git HEAD 与源码内容摘要分别记录了什么
- 如何避免通过删掉所有困难步骤得到看似很高的定位比例
- 为什么对照实验还需要分别关闭工具与修订的消融组
- 哪些项目效果已有记录，哪些还需要实际实验

## 当前可用的项目介绍

我用 Python 实现了一个仓库导览工具，面向第一次阅读陌生仓库的开发者。系统先建立源码快照和 AST 符号地图，再推荐入口。模型通过受限源码工具生成阅读步骤，程序检查符号定位和静态调用关系，发现问题后尝试一次修订，并保留未确认的连接。项目提供本地网页、CLI 和 CodeTour 导出，评测集固定了三个开源仓库的提交版本与十五道参考题。

真实模型质量对照与独立人工语义评分尚待完成。对外介绍中的收益数值应来自后续保存的原始实验结果。

## 演示顺序

先打开离线示例，展示从入口到跨文件调用的路线，点第二步对照源码，并展示静态连接来自第一步的具体行。随后打开一个真实仓库，展示候选入口、模块地图与锁定版本。配置模型后，再演示一次真实生成与缺口报告。最后查看固定评测的原始输出和评分记录。

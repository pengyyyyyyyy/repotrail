# 产品规格

## 使用场景

第一次阅读陌生 Python 仓库时，开发者需要找到入口、理解模块职责，并沿着一条流程追踪源码。RepoTrail 将仓库导航、逐步解释与源码阅读放在同一工作区。

## 产品范围

| 项目 | 规格 |
| --- | --- |
| 界面 | 本地网页与 Python CLI |
| 输入 | 公开 GitHub 仓库或本地克隆目录 |
| 分析语言 | Python |
| 模型接入 | 页面配置 API Key、服务地址和模型 ID |
| 模型协议 | Chat Completions 与 function calling |
| 配置流程 | 选择模板或自定义地址、获取模型、测试连接、保存使用 |
| 导览起点 | 推荐最多三条流程，由使用者选择 |
| 输出 | 网页导览、Markdown、JSON、CodeTour |
| 评测集 | Requests、Click、Flask 三个锁定版本仓库 |

## 交互流程

1. 在 API 接入中配置一个模型服务
2. 打开仓库，查看阅读起点和文件地图
3. 选择流程并生成阅读路线
4. 切换步骤，对照代码与解释
5. 按需要导出导览

工作区提供项目自带的示例仓库。API 配置通过本地服务读取和保存，保存后直接用于后续生成任务。

## 行为要求

- API Key 输入支持显示与隐藏，读取配置时返回密钥保存状态
- 切换服务地址后，需要为新地址提供对应密钥
- 获取模型失败时仍可手动输入模型 ID
- 连接测试检查模型响应和工具调用
- 保存配置、网页生成、CLI 与评测运行器使用同一个配置加载逻辑
- 生成任务启动时保存当次模型配置，后续编辑用于新任务
- 网页集中展示阅读起点、步骤解释与源码，技术校验数据记录在生成结果中
- 错误反馈说明需要处理的具体问题
- 输入上限为 300 个 Python 文件、单文件 200 KB、源码总计 4 MB

## 实现依据

服务商配置与模型获取的交互参考 OpenMinis。导览导出采用 CodeTour 格式，源码索引与生成工作流的参考资料见 research.md。
